# Альтернатива CEC для ПК / Google TV через ADB

[English version](README.md)

Служба Windows на C#, которая согласует работу Android / Google TV с использованием телевизора как монитора ПК через ADB вместо HDMI-CEC. Разработана и проверена с TCL 55C825.

**Автор кода: ChatGPT (OpenAI).** Sasha2dx предоставил требования, доступ к оборудованию и проверки на реальном телевизоре.

## Поведение

«Активен» означает, что телевизор используется в конфигурации рабочего стола Windows, а не что его панель включена. Все действия направлены на монитор и вход из конфигурации (HDMI1 в примере).

| Сценарий | Действие |
| --- | --- |
| Запуск службы, включая запуск до входа пользователя | Если дисплей активен, подключиться через ADB, разбудить ТВ, подтвердить Awake / ON и выбрать заданный HDMI-вход. |
| Выход ПК из сна | Та же последовательность пробуждения и выбора входа. |
| Неактивный дисплей стал активным | Разбудить ТВ и выбрать заданный HDMI-вход. |
| Активный дисплей стал неактивным | Если ТВ Awake / ON и его основная сессия соответствует заданному входу, отправить Home. Перед отправкой повторно проверить, что дисплей ещё неактивен. |
| ПК переходит в сон | Если дисплей активен, ТВ Awake / ON и выбран заданный вход, отправить Home. Общий лимит — 1,5 секунды. |
| Выключение или перезагрузка ПК | Аналогичная условная команда Home при PRESHUTDOWN, общий лимит — 10 секунд. |
| Ручная остановка или перезапуск службы | Остановка не отправляет Home. Запуск выполняет обычную стартовую последовательность. |
| ТВ показывает другой вход или Google TV Home | Условный переход на Home пропускается. Запуск, пробуждение и активация дисплея всё равно выбирают заданный вход, если дисплей активен. |

Приложение не выключает ТВ. Для Home используется `KEYCODE_HOME`, для пробуждения — `KEYCODE_WAKEUP`.

Текущий вход определяется сопоставлением `mainSessionToken` с `sessionToken` в карте сессий текущего пользователя из `dumpsys tv_input` и чтением `inputId` найденной сессии. Поиск ID во всём дампе недостаточен: там перечислены все доступные входы. Неизвестные, неоднозначные или неполные данные приводят к пропуску Home.

Наблюдение за дисплеем использует скрытое окно в сессии консоли, сообщения `WM_DISPLAYCHANGE` / `WM_DEVICECHANGE`, задержку стабилизации 400 мс и резервную проверку раз в 3 секунды. Первое чтение задаёт исходное состояние. Повторные неизменившиеся состояния ничего не делают; ошибки чтения не считаются отключением. Обратный переход отменяет незавершённое действие. При сне и пробуждении наблюдение сбрасывает исходное состояние.

## Требования

- Windows x64; права администратора для установки и управления службой.
- Стабильный .NET 9 SDK версии 9.0.305 или более новой ветки 9.0 (`global.json`) для сборки. Публикуемое приложение содержит runtime.
- Android SDK Platform-Tools для Windows: `adb.exe`, `AdbWinApi.dll`, `AdbWinUsbApi.dll`.
- Android / Google TV с разрешённым сетевым ADB, доступный по сети в ожидании. При необходимости включить сетевое ожидание / быстрый запуск в настройках ТВ.
- Постоянный сетевой адрес ТВ и HDMI-подключение к ПК.

Проверено на TCL 55C825. Другие телевизоры могут иметь другие URI входов и формат диагностических данных: сначала настройте и проверьте их.

## Сборка из исходников

```powershell
git clone git@github.com:Sasha2dx/CEC-alternative-for-PC-Google-TV-using-ADB.git
cd CEC-alternative-for-PC-Google-TV-using-ADB
dotnet build TCL-ADB-CEC.sln -c Release
dotnet run --project Tests\Tests.csproj -c Release
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Publish.ps1 -AdbDirectory 'C:\Android\platform-tools' -OutputDirectory publish
```

Укажите свою папку Platform-Tools. `-AdbDirectory` можно опустить, если `adb.exe` есть в PATH. Публикация создаёт автономное приложение `win-x64`, копирует конфигурацию и три файла ADB в `publish`. Ключи ADB и результаты сборки исключены из Git. `-ExecutionPolicy Bypass` действует только для этого процесса PowerShell.

## Настройка телевизора

Измените `publish\appsettings.json` **до установки**. Файл `TclTvWake\appsettings.json` содержит рабочий пример для TCL, а не универсальные настройки; измените его до публикации, если хотите автоматически копировать свои значения.

| Настройка | Значение |
| --- | --- |
| `Endpoint` | Адрес ADB телевизора с портом, например `192.168.1.95:5555`. |
| `MonitorId` | Префикс ID монитора Windows, например `MONITOR\XXX9615`; в JSON обратный слеш удваивается. |
| `HdmiUri` | Полный passthrough URI нужного входа телевизора. |
| `AdbPath` | Путь к ADB; относительный путь считается от папки приложения. По умолчанию `adb/adb.exe`. |
| `AdbServerPort` | Порт отдельного локального сервера ADB. По умолчанию 5038; используйте отдельно от обычного 5037. |
| `CommandTimeoutSeconds` | Таймаут одной команды ADB. По умолчанию 15 секунд; для Home есть дополнительный общий лимит. |
| `Attempts` | Максимум попыток при запуске, пробуждении или активации дисплея. По умолчанию 12. |
| `RetrySeconds` | Пауза между попытками. По умолчанию 5 секунд. |
| `WakeDelaySeconds` | Пауза после пробуждения перед проверкой питания. По умолчанию 3 секунды. |

Узнать ID монитора Windows:

```powershell
.\publish\TclTvWake.exe --list-displays
```

Авторизуйте ADB со своим адресом ТВ, подтвердите запрос пультом (разрешите дальнейшие подключения, если предлагается). Затем выберите нужный HDMI-вход пультом:

```powershell
adb connect 192.168.1.95:5555
adb -s 192.168.1.95:5555 shell dumpsys tv_input
```

Найдите `inputId` основной сессии. Закодируйте ID как URL и добавьте после `content://android.media.tv/passthrough/`, получив `HdmiUri`. В комплектной конфигурации указан проверенный URI HDMI1 для TCL. Адрес, ID монитора и URI обязательны в конфигурации; в рабочем C# коде нет запасных значений для конкретного ТВ.

## Установка и запуск

В **PowerShell администратора**, из папки репозитория:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install-Service.ps1 -PublishDirectory publish
```

Скрипт копирует приложение в `%ProgramFiles%\TclTvWake`, устанавливает или обновляет автоматическую службу `TclTvWake` от LocalSystem, настраивает восстановление и сразу запускает её. Запуск может включить ТВ и выбрать заданный вход.

Копируется авторизованный приватный ADB-ключ из `%USERPROFILE%\.android\adbkey`. Если используется другой аккаунт администратора, передайте `-AdbKey 'C:\Users\YourUser\.android\adbkey'`. Не публикуйте приватный ключ. Доступ службы может потребовать однократного подтверждения на ТВ. Папки приложения/ключей и данных доступны только SYSTEM и администраторам.

Из сессии 0 нельзя надёжно проверить дисплеи физической консоли. Поэтому служба запускает короткие невидимые вспомогательные процессы с SYSTEM-токеном winlogon консольной сессии. Пароль пользователя и ярлык автозагрузки не нужны.

После установки редактируйте `%ProgramFiles%\TclTvWake\appsettings.json` с повышенными правами и перезапускайте службу. Обновление из папки публикации заменяет установленные настройки, поэтому предварительно сохраните свои значения в этой папке.

```powershell
Get-Service TclTvWake
Restart-Service TclTvWake
Get-Content "$env:ProgramData\TclTvWake\service.log" -Tail 30
```

Ручные команды для установленного приложения из повышенного PowerShell:

```powershell
& "$env:ProgramFiles\TclTvWake\TclTvWake.exe" --once
& "$env:ProgramFiles\TclTvWake\TclTvWake.exe" --home-if-hdmi1
& "$env:ProgramFiles\TclTvWake\TclTvWake.exe" --home-sleep-budget
```

`--once` выполняет включение и выбор входа. Команды Home требуют активного дисплея Windows и имеют общий лимит 10 секунд и 1,5 секунды соответственно. Код выхода 0 означает успех; 1 — пропуск или ошибку. Для ручного запуска опубликованной копии поместите авторизованный `adbkey` в её папку `keys`, если отдельный сервер ADB ещё не запущен с этим ключом. `--service` предназначен для диспетчера служб; `--probe` и `--watch-change` — внутренние режимы помощников.

## Проверки и ограничения

Проверьте запуск до входа пользователя, сон/пробуждение, выключение, оба перехода активности дисплея, защиту для неактивного дисплея и пропуск Home на другом входе. Основные сценарии проверены на TCL; отдельные проверки выключения ПК на HDMI2 и отключения дисплея на HDMI2 не зафиксированы в предоставленных журналах. Автотесты проверяют парсер входа, отслеживание переходов и проверку конфигурации.

- Перед сном сеть может отключиться раньше завершения попытки Home за 1,5 секунды. При ошибках/таймауте действие пропускается; сон не запрещается. В реальных проверках дополнительные проверки дисплея завершались близко к лимиту.
- Восстановление сети и ADB может задерживать включение и выбор входа. Ограниченные повторные попытки обрабатывают `offline`, закрытые соединения и временную недоступность.
- При сне/выключении Windows может уже считать дисплей неактивным: тогда Home пропускается. Физическое подключение определяется по состоянию дисплея Windows, которое может обновляться с задержкой после извлечения кабеля.
- Проверка входа и доставка команды не атомарны: переключение пультом во время проверки может изменить результат.
- `Activity not started ... brought to the front` может быть нормальным, если TV Activity уже работает. Проверяйте питание и доставку intent по журналу.
- Журнал: `%ProgramData%\TclTvWake\service.log`, около 2 МБ плюс один предыдущий файл; чтение доступно администраторам.

## Обновление, откат и удаление

Публикуйте в другую папку (например `-OutputDirectory publish-v2`) и устанавливайте с `-PublishDirectory publish-v2`. Для отката сохраните проверенную папку публикации и установите её повторно. Предыдущие версии также сохранены в истории Git.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Uninstall-Service.ps1
```

Запускайте удаление от администратора. Скрипт удаляет службу и останавливает её сервер ADB на настроенном порту. Файлы приложения, настройки, ключи и журнал сохраняются для восстановления.
